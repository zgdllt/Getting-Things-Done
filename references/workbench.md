# Getting Things Done 工作台

## 交互

- 桌面入口与 `~/Applications/Getting Things Done.app` 使用同一原生窗口，命令为 `python3 ~/.codex/skills/personal-gtd/scripts/gtd.py workbench`。
- **今天**：读取已有系统提醒事项与日程，快速收集想法，点击圆圈完成明确的系统任务。
- **待澄清**：查看候选、建议分类、原始来源片段及问题；「保存答复并整理」先持久保存，再立即用模型回应并修订下一步，不等待历史积压。卡片显示处理中、结果或可重试错误。必要时追问；用户明确结束的候选进入「已收束」。已保存过的答复可用「依据答复整理」触发。保存和模型整理均不创建正式任务。整理完成后可选中候选、编辑行动标题、选择已有列表和截止日，预览后明确确认保存。
- **项目与等待**：仅将已确认候选作为正式项目来源，并核对关联的实际系统事项。已完成或当前快照未找到的任务不计作活跃等待。
- **回顾**：查看候选、问题、逾期任务、等待和近期安排。回顾复选框只表示本次检查进度。
- **在 Codex 继续**：复制澄清摘要会保留已答信息和没有关联候选的问题；实际系统日程调整可在对话中明确确认。
- **左下角设置**：模型、推理强度、后台连接、通知和系统应用权限集中在此。默认 `gpt-6.1-terra / high`，模型目录沿用本机 Codex 列表，也可填写服务商支持的模型 ID。设置写入私有 GTD 配置，从下一次 GTD 模型调用生效；provider/auth 与普通 Codex 对话默认值沿用原配置。后台与权限区展示实际状态，权限由系统设置管理。

页面通常每 15 秒读取本地缓存；有答复整理任务时每秒检查结果。结果更新会保留正在编辑的草稿、焦点与光标。设置或确认弹窗打开时不重建表单；收集和待澄清答复草稿保存在工作台来源的 localStorage，提交成功后清除。系统快照由订阅或“刷新系统清单”更新，页面显示同步时间、不可读状态和失败。线索来源状态会区分适配器、摘要数量以及来源不可读或超过 36 小时无变化的断档风险。

## 通知与恢复

通知标题取具体候选摘要，正文说明待判断的问题，并附同批其他事项摘要。点击原生通知进入 app 的待澄清页。首次未完成授权时，原有系统通知通道也包含摘要，但不提供直达。

每个通知批次有固定成员、内容和 ID。发送端持久保存请求与回执；原生端用 rename 接管。结果不明确时不标记为已通知，也不跨通道重复发送；新的问题另建批次，不受旧批次阻塞。接管后进程退出等不明确状态需在本机核对。

桌面、通知和 `personalgtd://inbox` 等入口在加载前检查本地服务。服务不在时恢复并等待监听；应用已打开时同样能切换目标页。原生窗口只加载配置中精确端口的 loopback 页面；用户点击的来源网页在浏览器打开。剪贴板桥只接受同来源主 frame。

## 状态归属

| 数据 | 归属 |
| --- | --- |
| 正式任务、完成状态 | 系统提醒事项 |
| 时间安排 | 系统日历 |
| 候选、证据、问题、答复 | 私有 SQLite |
| 系统快照 | 带读取时间与权限状态的缓存 |
| 线索来源 | Computer History 适配器与本机 Markdown memory；均只产生候选证据 |
| 写入与通知回执 | 本地操作日志，不替代正式系统状态 |

工作台与历史订阅是两个独立 LaunchAgent，名称前缀为 `local.codex.personal-gtd`。退出窗口不等于暂停订阅；停止当前 job 与移除未来登录配置是两步。

后台模型提取可以并行进行；实际候选提交、答复、忽略与正式写入共用事项锁。预览带候选版本，journal 关联候选，避免旧预览或结果不明后重新创建重复事项。

答复整理使用独立持久队列与进程锁；模型调用期间不持有事项锁或 SQLite 写事务。重启工作台可恢复未完成任务，失败项由用户重试。提交结果时核对候选版本和问题/答复，迟到结果不覆盖新决定；历史积压不能重新塞回旧问题，真实较新的观察仍能提出变更供用户确认。已进入正式清单的事项只展示回复与建议，完成状态仍以提醒事项为准。

历史整理和每批答复整理都会调用模型并消耗现有服务商额度；打开设置、保存模型选择、查看已有结果不调用模型。

如果当前活动与较早的 memory 摘要有具体词汇关联，后台会把最多四条旧摘要作为回溯背景提供给模型。回溯线索会保留来源路径和历史标记；它不能单独恢复旧任务、设置截止日或证明事项已完成。
