# Finder 标签资料整理

> 2026-11-06：真实递归扫描产生 623,510 项、约 374 MB JSON，造成明显资源问题。该方案已被替代：现在一个 Codex 项目根文件夹只是一项，手动加入的文件夹也不展开；结果使用独立 SQLite 索引，API 每页最多 100 项、UI 每页 40 项。旧大缓存保持隔离，绝不自动恢复。隔离测试、浏览器与可搬移原生 App 检查通过；小样本通过不等于任意规模都已验收。

## 已确认的设计

- 默认从 Codex 的本机项目根目录开始，按真实路径去重；用户可再添加文件／文件夹。远程主机路径不纳入本机 Finder 标签操作。agent 主动建议，确认后才写标签。
- 使用已有 Finder 标签，文件保持原位，不创建一套主题或资料类型标签。
- 按重要／紧急程度组织；绿色固定表示「已完成」，不改变提醒事项里的任务状态。
- 四象限的初始建议映射为红色＝重要且紧急、黄色＝重要不紧急、橙色＝紧急但较不重要、灰色＝可暂缓；用户可在资料设置中调整。它是可修改的初始设置，不代表已经获知用户原有的颜色约定。
- 原有标签保留；应用前显示将添加的标签，撤销只移除该次实际添加的标签。
- 闲置期限默认 30 天，可在左下角「设置 → 资料整理与缓存」修改。长期无对话、无文件变动时建议灰色。用户进一步确认：活动证据不足也建议灰色，理由标明默认暂缓，不能宣称已经证实长期无改动。近期明确有活动的项目再结合任务背景请求模型建议；原有绿色完成标记优先。

## 用户路径与状态

资料 → 同步 Codex 项目／手动添加所选项 → 读取根目录名称、标签与活动 → agent 建议与理由 → 编辑／忽略 → 预览 → 确认应用 → Finder 回读 → 按标签找资料／撤销本次添加。

选择文件夹只代表文件夹本身，不列出孩子，也不给孩子自动打标签。旧递归扫描协议已废弃：HTTP `/api/files/scan` 和携带 `recursive` 参数的登记请求均返回 410；新界面使用 `/api/files/refresh`，登记不含递归字段。原生 `files-scan` 直接报废弃错误，新 `files-inspect` 只接受明确 `paths`，拒绝旧的 `scopes`／`recursive` 结构，不做静默兼容。只读取所选项元数据，不读取文件正文。Codex 项目与对话活动仅读本地元数据，不打开对话正文。

FSEvents 观察所选根目录的变动，按根目录合并为活动时间，不建立后代文件清单；记录从加入观察后开始，不把根目录旧 mtime 解释为整棵树未改。工作台状态目录的事件被排除。项目元数据和根目录每分钟重新核对，显式刷新可重算；构建产生大量事件不会逐文件调用模型。建议使用 GTD 已选模型；浏览、筛选、应用、撤销、灰色默认规则和缓存清理不调用模型。不把修改时间解释成截止日期，也不凭文件名宣称已经完成。

标签在文件系统中是真实状态；本地整理库保存工作区、建议、预览和操作回执。模型不能写文件。选择范围之外的路径不能通过建议结果进入应用计划。预览后文件被替换、内容或标签发生变化时，该项要求重新预览；批量执行逐项报告失败，已成功项不重复执行。撤销保留后来由用户添加的其他标签。

## 取消与缓存清理

整理目录为 `$CODEX_HOME/personal-gtd/file-organizer/`，未设置 CODEX_HOME 时为 `~/.codex/personal-gtd/file-organizer/`：

- `library.sqlite3` 及 `-wal`、`-shm`：分页索引、范围、设置、建议与操作索引。
- `library.json`：很小的迁移指向文件，不再保存全量扫描结果。
- `library-paused-*.json`：已隔离的旧扫描存档，不会自动读取或恢复。
- `<32位UUID>.json`：确认预览及真实标签写入回执，用于撤销；清理扫描缓存保留这些文件。
- `paused`：暂停标志，服务重启也保留；仅明确恢复才移除。

左下角「设置 → 资料整理与缓存」展示实际目录、索引与旧存档大小，用户勾选后清理。默认只清理所选旧存档；可另选清空当前索引，操作会先终止资料进程组并保持暂停，保留范围、设置和撤销回执。不清理原文件、Finder 标签、提醒事项、日历或 Computer History。

资料页提供暂停／恢复。暂停终止扫描、活动观察与模型子进程所在进程组；即使组长先退出，仍核对整个组，必要时升级终止。普通 GTD 历史处理独立运行。

也可从命令行查看或清理旧存档，以下命令不会触发扫描：

```sh
python3 ~/.codex/skills/personal-gtd/scripts/gtd_files.py --cache-info
python3 ~/.codex/skills/personal-gtd/scripts/gtd_files.py --clear-archived-cache
```

不要删除整个 `personal-gtd` 目录；其中还有正式任务操作日志、待澄清答复与模型设置。

## 参考与取舍

- Apple Finder 原生标签支持给文件和文件夹多重标记并按标签查找；沿用现有颜色，避免维护额外的文件分类副本：[Apple 使用说明](https://support.apple.com/guide/mac-help/tag-files-and-folders-mchlp15236/mac)。
- 原生桥使用 Foundation 的 `URLResourceValues.tagNames` 读取及回读：[Apple API](https://developer.apple.com/documentation/foundation/urlresourcevalues/tagnames)。单独使用名称 setter 会丢失不在全局目录中的自定义标签颜色，已用临时文件复现，因此写入按原始 Finder 扩展属性保留名称与颜色，只合并本次新增或撤销的标签。给文件夹打标签不会自动给孩子打标签，所以递归范围和逐项预览显式展示。
- 借鉴 TagSpaces 的按标签检索路径；文件元数据由 Finder 管理，GTD 不改文件名，也不创建 sidecar 标签文件：[TagSpaces 文档](https://docs.tagspaces.org/tagging/)。本项目增加的是结合已确认任务背景的优先级建议及确认流程。
